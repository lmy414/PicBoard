# 本地版交互修复计划

## 最新用户修复批次：快捷键、小地图与悬浮球

本批次以用户最新反馈为准，继续交给原 Luna 执行者。

- Ctrl+C：作用于当前预览图片或选中图片，复制图片文件；编辑输入框时保留文字复制。
- Delete：移除当前画布预览/选中图片；同步关闭失效预览；已归档原文件保留。分类库不以此快捷键删除归档资源。
- 画布小地图常驻，展示图片范围和可见视口，支持点击/拖动导航；兼容负坐标与空画布。
- 画布、分类库和预览中的长文件名均在容器内截断，悬停可查完整名称。
- 移除文件拖出入口，以复制文件并粘贴到其他应用为对外取图方式；画布内移动继续保留。
- 悬浮球短点展开，长按约250ms进入拖动，跟随鼠标移动窗口；拖后不误展开，拖中形变、松开回弹，取消/失焦结束拖动。
- 眼睛跟随使用有限视角和平滑变化，鼠标距离再远也不翻转/乱转；保留眨眼和呼吸。

验收关注：预览和多选两种状态的复制/删除、输入框快捷键、不误删已归档图片、小地图导航事件隔离、长名实际布局、球拖动取消和跨显示器边界、极远鼠标视角限幅。系统文件剪贴板需以原生读取文件列表验证，不能只断言buffer字节正确。

基于 2026-09-06 当前源代码审查。主任务负责计划和验收；具体修改由 gpt-5.6-luna 执行。代码发现与真实桌面验收需区分。

## P0：图片可见、操作对象正确、数据不丢

1. 初始视角为 (-900,-500)，新图片位置却从 (80,80) 开始，因此导入图片处于视口外。统一坐标，导入定位当前视口，增加“定位全部图片”，缩放围绕视口中心或鼠标。允许负坐标，取消伪无限画布边界。
2. 画布切换只改 React 状态，未写入后端 activeCanvasId，后续接口返回旧画布。新增持久化切换接口，每画布保存视角；切换后清空选择，防止跨画布误操作。
3. state.json 原地覆盖、写入不串行；读取任意异常直接重建并覆盖文件。改为串行事务、原子替换、校验与备份，损坏时保护原文件并报告错误。文件分类、删除与元数据提交失败必须可恢复。测试只能操作独立临时目录。

## P1：完成实际交互闭环

4. 图片主体移动、空白平移、文件拖出使用明确独立手势；处理缩放坐标、拖动阈值、取消及指针丢失；避免点击触发写盘和全库预览读取。
5. 面板展开尺寸保持在当前显示器工作区；支持移动悬浮窗、收起、退出，控件区域不能被窗口拖动拦截。
6. 用应用内输入弹窗替换 window.prompt，覆盖画布重命名、新建分类；删除画布显示未归档清理与已归档保留提示。
7. 分类库点击必须显示可见快捷操作，支持复制文件、文件拖出、重新分类；库内不显示误导性的“从画布移除”。切换视图清空选择。
8. 导入和粘贴处理真实图片文件及剪贴板图片；输入框粘贴文字正常；无图片、失败、成功和忙碌均有反馈。复制文件多选不能偷偷只复制第一张；未验证的平台行为不能宣称成功。
9. 重新分类保证分类关系与实际存储一致。分类使用稳定标识避免 Windows 文件夹名称问题。

## P2：可用性和性能

10. 缩略图保持图片比例、长文件名截断；预览缓存，避免每次移动读取全库原图；保留现有资源兼容性。
11. 启动检查核实实际 Electron 窗口和渲染内容；构建通过不能代表交互验收通过。

## 验收场景

- 空画布导入后立刻看到图片，移出当前视野后能一键定位回来。
- 50%、100%、150% 缩放拖动距离正确；取消拖动不留错误位置。
- 画布 2 导入、移动、分类后仍留在画布 2；重启保留画布、资源与视角。
- 单张和批量分类；移除未分类清理资源，移除已分类保留库资源；删除画布同理。
- 复制文件与系统文件拖出必须注明是否已做跨应用实测。
- 屏幕边缘展开后面板全可见；新建分类、重命名、退出入口可操作。
- 并发保存、坏 JSON、提交失败不得静默覆盖用户原数据。
