## 1. 产品定位与本轮边界

**一个随手接住图片、快速整理、用完退回桌面角落的个人效率工具。**

简约不是缩小字号、藏掉必要操作，而是降低无关信息与装饰的存在感。图片是主体，小球是入口；弹性表达触感，不承担持续吸引注意的任务。

本次完善现有能力的样式、交互反馈、动画生命周期与可访问性。冻结图片收集、临时画布、分类、预览、复制/粘贴、窗口拖动等业务范围。依据用户最新反馈，明确加入自定义拾色器、定制下拉框和路径选择交互；这是既有设置的操作升级，不代表已授权改变实际存储根或搬迁数据。

明确不做：AI、账号、云同步、新业务页、全局快捷键、搜索系统、主题商店、新图片格式工程、窗口吸附、文件拖出、磁吸/惯性移动窗口、真实数据搬迁、新原生多窗口、一次性重构整个 React 应用。

50MB 仍指**自有分发包**，不是 node_modules/target 或运行目录；本轮不离线捆绑 WebView2。不能拿 debug exe 大小或前端 gzip 数字作为分发验收。

## 4. 推荐视觉方案：白纸面板 + 低饱和强调色 + 有触感的小球

### 4.1 风格规则

1. 工作面板使用近白底、深灰文字、浅灰分隔；去除整面板/弹层的纯黑描边。
2. 一个低饱和绿色 UI 强调色用于选中、焦点和成功，红色仅错误/危险动作；小球保留用户已选择的颜色，不强行同步 UI 色。
3. 卡片采用精细层级而非“无设计的白盒子”：明确图片区、名称区、操作区，薄边线/浅接触影/一致留白；静置克制，悬浮层有清晰高度差。小球保留轻接触影，不做常驻发光描边。
4. 不新增大标题横幅、营销副标题、引导页、侧边栏、常驻状态栏和装饰粒子。
5. 不以隐藏全部按钮换简约；常用操作直达，低频操作进入现有工具区或就近浮层。

### 4.2 Token 初值（待视觉验收微调，非硬编码散落）

| 类别 | 建议值/规则 |
|---|---|
| 背景 | panel #FAFAF9；surface #FFFFFF；subtle #F2F3F2 |
| 文字 | primary #202421；secondary #616862；faint #7A817B，仅辅助信息；实际搭配须检查对比 |
| 分隔 | #E2E5E1；选中 #23856B；危险 #B84646 |
| 字体 | 系统字体优先（Segoe UI / Microsoft YaHei）；不下载/捆绑新字体 |
| 字号 | 正文/控件13px，次级12px，说明11px，区域标题14–16px；9px不承担必要信息 |
| 间距 | 4/8/12/16/24px；卡片内边距统一，避免同层3/5/7混杂 |
| 圆角 | 控件8px、卡片10–12px、面板/预览14–16px；胶囊仅标签/计数 |
| 命中目标 | 常规按钮至少32×32逻辑px；图标本体16–18px；不得把32px画满成大按钮 |
| 阴影 | 卡片0或极浅一层；浮层一层柔和投影；不可用80px模糊阴影堆“高级感” |
| 焦点 | 2px清晰focus-visible轮廓，不依赖颜色单独区分选中 |

### 4.3 各界面减法

**折叠小球**
- 原生88×88与稳定命中区保留；视觉球体、轻影及形变均留在窗口边界内。
- 默认仅眼神/偶发眨眼，小幅呼吸；不持续上下漂浮，不常驻光环/星点。
- 批量导入成功只播放一次完整吞咽；计数>99显示99+，完整数量通过可访问文字/title呈现。
- 明确的嘴巴开合和接收物是此次必要设计，不接受只有scale/闪绿/✓作为吞图交付。详见5.5。
- 拖入、忙碌、成功、错误各一个明确反馈；不同时叠两枚徽章+光晕+粒子。
- 颜色/形状等旧偏好不覆盖。新的克制默认仅用于无历史设置或用户主动恢复默认。

**展开画板**
- 顶部一行：短产品标识、画布/分类库切换、设置、工具、收起/关闭；移除重复副标题。
- 当前画布名始终可辨识；切换/新建入口不藏到多层菜单。缩放、定位全部仍在现有工具区。
- 长串快捷键说明移到相应按钮title和空态短说明，不另建帮助页。
- 点阵降低对比，图片主导视觉；空态固定视口中心，不随世界坐标被平移走。
- 小地图：空画布不显示，有图保留；先降低对比，默认不引入自动折叠机制。
- 不更改持久化的图片坐标/宽高协议，不擅自改变布局算法以适配新外观。

**图片与快捷分类**
- hover：边框/浅背景提示；selected：稳定强调边框，不持续抬升；dragging：轻微抬起，无持续旋转。
- 单击选中、Shift多选、双击预览、Ctrl+C复制等语义原样保留。
- 已有分类浮层精简标题和说明，分类项中性底而不是每项黑色主按钮；新增/移除用次级动作区分。
- 浮层动态量尺寸、左右翻转、底边限高滚动；图片拖动中不弹出/追着鼠标跳。

**分类库与预览**
- 分类库减少重复描述、空分类大片留白与卡片常驻按钮重量；重新分类/复制保留可发现入口。
- 非触摸设备可hover/focus-within显示次级操作，但操作位预留，不能造成布局跳动；触摸/键盘仍可达。
- 网格按容器自适应，避免窄窗口固定三列；长文件名截断但保留完整可访问文本。
- 预览突出图片，名称/归档状态为次级；操作固定于底部且不挤压图像，长图不撑出原生窗口。
- 只保留一层浅遮罩；不是所有背景都加高强度blur。

**设置**
- 去PERSONALIZE装饰、大标题与介绍段，保留“外观与动效 / 路径偏好 / 分类”三个轻分组。
- 保留设置预览球，但头部标识不再另运行一个完整动画引擎。
- 高级外观参数可收进一个默认折叠区，原有值/操作完整保留；不是删除既有个性化能力。
- 路径改为纵向单列的目录选择行，以“选择文件夹”代替强制手输，同时保留直接编辑作为次级入口；选择目录只更新原有偏好，不搬迁文件或切换实际数据根。详见4.5。

### 4.4 现代控件与卡片：不只是给原生控件换边框

**三类卡片，而不是全站同一个白色圆角框**

| 类型 | 结构与质感 | 状态规则 |
|---|---|---|
| 图片卡片 | 图像容器为主，轻边线与一致内边距；透明图用低对比棋盘底；名称单行、状态点次级 | 静置低影，hover仅微提亮，selected用稳定强调线；drag仅内层抬起；不能改图片坐标/持久化宽高合同 |
| 分类/预览浮层 | 清晰标题行、内容区、次级动作；8–12px分组间距；一层更高投影和薄边框 | 160–200ms淡入/4px位移，边缘避让、内容滚动；不做满屏磨砂或大幅缩放 |
| 设置分组 | 一层轻背景面，不套多重卡片；标签和字段基线对齐、主次说明分离 | 错误/禁用/焦点样式一致，正文不小于12–13px；没有信息的区域不加装饰 |

卡片升级必须包含内容结构、可读性、状态和操作位置；只换颜色、加大radius、增加投影不算完成。阴影初值：静态卡片`0 1px 2px rgba(20,28,22,.04)`；popover`0 8px 24px rgba(20,28,22,.12)`，具体WebView效果实测后调。

**统一Popover壳**
- 拾色器、下拉列表、已有菜单共享边界、阴影、圆角、上下翻转、max-height滚动、Esc/点击外部关闭和焦点返回。
- 使用根overlay层避免设置滚动容器裁切，优先真实测量而不是猜高度；关闭层不拦截后续点击。
- 不用自定义绘制整套文件管理器来统一风格；系统目录对话框是合理的原生能力边界。

**自定义拾色器**
- 用带当前色块、HEX值和展开箭头的紧凑触发器替换眼睛颜色原生`input[type=color]`弹窗。
- 应用内popover包含二维饱和度/明度区域、色相滑条、可编辑`#RRGGBB`和少量现有预设；不增加取屏幕色/历史云同步/渐变/alpha等功能。
- 保留当前schema六位HEX；无效HEX显示就近错误，不写入错误偏好；按钮/滑条可键盘操作，二维区域不能成为唯一入口。
- 拖动实时预览，松手或合法值确认时合并持久化，避免每像素都同步写localStorage；Esc撤销本次未提交预览，外点只提交合法值。
- 主体颜色当前是colorId预设：保留预设映射，不擅自将其改成任意色字符串或覆盖旧偏好；视觉外壳可统一。

**定制下拉框/滑条/开关**
- 身体形状、表情模式改为自定义触发器+listbox：选中勾、选项hover、高度32–36px、轻分隔，形状可带微型轮廓预览；不是只给原生select加CSS。
- 方向键/Home/End导航，Enter提交、Esc取消、focus恢复；表情值仍为原random/rest/spark；映射中文标签，不把内部id直接当体验文案。
- 色块、滑条、开关同一focus-ring和禁用规则，选中色块不靠放大来挤邻居；range可保留原生input行为但统一轨道/拇指样式。

### 4.5 路径选择：减少手输，同时不欺骗存储语义

建议每项一行：`字段名 | 当前目录（中间省略） | 文件夹按钮`，完整路径可聚焦复制/查看，选择按钮最少32px命中区。点击打开受控系统目录选择对话框，初始位置仅用有效已存目录，否则使用安全默认；取消不更改，选完刷新对应字段，异常就近提示。

**必须区分两个范围：**
1. 本轮纳入：把现有路径偏好的手输改为点选，保留可选手动编辑；标题明确“目录偏好”，提示“不会移动现有文件，也不会切换本次图片库”。不能显示“已更换存储位置”。
2. 尚未批准：更改真实数据根、多个分类目录分别写文件、移动旧图片/切换库。这涉及原存储相对路径、事务与数据兼容，不是选目录按钮的附带行为。如果用户想要选完立即生效，须先单列方案确认。

Rust/Tauri 端使用窄用途目录选择器（仅主窗、directory=true、单选）。不把通用文件系统权限暴露给网页；目录选择本身不创建目录/读图片/移动数据。对话框焦点返回调用按钮，打开时不意外触发窗口拖动。

## 5. 动效方案：有弹性，但能立即停下来

### 5.1 一个反馈体系，而不是每处不同曲线

将动效分成三档：
- **即时响应**：按下/焦点/拖动，不等动画结束才执行；按下约60–90ms。
- **触感回弹**：小球、成功接收，约240–360ms；只允许一次轻过冲。
- **界面过渡**：弹层/页切换约140–220ms，以opacity+少量translate为主，文本不做明显缩放。

可以用现有BotEngine + CSS/WAAPI实现，不默认引入Framer Motion等新依赖。若确实需要可重定向弹簧，仅一个小型共享实现，不写第二套角色引擎。

可选弹簧起点：质量1、刚度300–400、阻尼26–32；仅作调参初值，不是GrokBot测量值。实际验收以响应、过冲和收稳时间为准。

### 5.2 小球状态/反馈参数

| 场景 | 建议效果 | 约束 |
|---|---|---|
| 静置 | 极轻呼吸，约5–7秒/周期；不再高频随机切换 | 默认形变量≤1%，不持续平移窗口；视野之外暂停 |
| 指针靠近 | 眼神先跟随，主体至多放大1.02 | 取消旋转光环与漂浮粒子；离开回中性，避免永远盯极限角度 |
| 按下 | 纵向压至约0.94、横向1.02 | 只变视觉层，命中区不缩；不要触发分类/窗口拖动重复事件 |
| 拖小球 | 手势阈值仍250ms/6px；轻压扁表示抓住 | 原生窗口严格跟手，不加弹簧追随；松手立即停止，视觉独立回弹 |
| 文件进入 | 眼神朝接收点、明显张口，轻压低姿态 | File drag与window drag分开；只在窗口实际收到dragenter后触发，不宣称窗口外能感知文件 |
| 导入进行中 | 接收物停在嘴边/口前等待，一处低频忙提示 | 超过150–200ms才显示忙提示；不让成功动画遮盖失败；嘴不无限开合 |
| 导入成功 | 接收物缩入口内→闭口→一次吞咽，约420–600ms，最后显示对齐的勾 | 身体峰值形变量≤6%，口型独立；不等动画才入库；批量一次，不排长队 |
| 导入失败 | 短边框/符号反馈，最多2px轻摆 | 不连续抖动；折叠状态也有可读原因入口，展开后保留详情 |

状态优先级：显式操作反馈（处理/结果）高于普通hover/idle；拖窗期间禁止随机表情抢动画。掉帧/重复触发采用最新意图，不积累动画队列。

motion控制幅度（0=没有非必要形变）；speed控制时长/时钟速率；两者不互相冒充。设置改变保持单调连续时钟，不让已有引擎在旧关键帧上突然回到t=0。

### 5.3 展开/收起：先确保原生窗口与内容一致

推荐最小状态：collapsed → opening → expanded → closing；每次意图带序号，完成回调必须确认仍是最新意图。

- 展开：立即给按压反馈 → 等待host扩窗成功 → 下一帧呈现内容，180–220ms淡入/轻移入。
- 收起：内容120–160ms退场 → host缩窗成功 → 显示小球回弹。
- 失败：恢复已确认的窗口状态与可用UI、给出错误；不能让React认为已展开而窗口仍88×88。
- 快速连点：合并为最新目标或明确短暂防重入，禁止动画/IPC堆积导致最后状态错误。
- 第一阶段**不做**从88×88到660×760的原生尺寸逐帧插值、不做“整张画板缩进小球”的复杂变形；窗口大小改变与内容缓动分开，减少裁切/白闪风险。
- 动效不能增加拖动延迟、改变画板数据或抢焦点。展开/收起位置沿用当前几何合同。

### 5.4 动画与定位解耦

- 小球：外层稳定命中，内部独立视觉transform，眼睛由现有引擎负责。
- 图片：外层坐标位移，内层轻抬起；松手时提交最终坐标，不为美观加坐标缓动。
- toast/浮层：外层布局定位（包括translateX居中），内层opacity/translateY过渡，避免pop-in覆盖定位transform。
- 同一帧不要同时由CSS animation、React inline transform和BotEngine控制同一属性。
- 预览/分类浮层退场不挂不可点遮罩；退出后恢复焦点到来源图片或触发按钮。

### 5.5 必须看得懂的“吃图”：口型不是放大眼睛

**目标故事：我把图片放到嘴边，它确实接住，保存成功后吞进去。** 默认其他界面保持安静，但用户主动投喂时允许明确的角色表演；不用全屏特效补足小球内部表达。

| 阶段 | 视觉与时序初值 | 数据/事件边界 |
|---|---|---|
| idle | 中性表情，无常驻夸张嘴巴 | 不把随机状态当作收图进度 |
| drag-over | 100–160ms张口：脸下部出现真正椭圆/圆角嘴洞，眼睛略上移并关注接收点；口腔内明暗有层次 | 由Files dragenter/over触发；文件类型在dragover阶段不可读时只表达“准备接收”，不能保证有效 |
| receiving | 用户松手后在嘴前出现一张极简图片小片；处理超200ms维持等待姿态 | 立即开始原有importImages，不等待动画；拖出/取消仅闭口，不显示成功 |
| success | 返回成功后，小片120–180ms沿短轨迹缩向嘴中心并被mouth mask裁切；随后闭口、吞咽形变、眼神放松，总420–600ms | 真实入库成功才吞咽、计数更新；动画时长不是业务延迟，不能制造重复导入 |
| settled | 终点显示约0.8秒小SVG勾后消失，恢复中性 | 批量一次反馈，不按每张图片排队；新操作可打断旧收尾 |
| error | 小片淡出而非被吞，嘴回中性，错误标识/原因可读 | 保留错误详情，不播成功勾、不增加成功计数 |

**如何实现而不破坏第三方引擎**
- 当前BotFrame的notch是通知缺口、wide是眼型；均不能冒充mouth。新增本地SVG口型层/口型参数（开合进度、口中心、宽高），统一视图坐标且限制在主体轮廓内；保留Bloub第三方文件/许可证。
- 口腔颜色按主体明暗选择：深色身体上用浅嘴缘+深口腔/小舌面，浅色身体用深嘴洞；不依赖一个白色洞在所有色下都清晰。眼睛与嘴不能互相重叠。
- 在实际88×88窗口下验收张口可辨识，口型目标视觉宽约12–16逻辑px、高8–12px；按当前bodyPath实际可用区域调整，不能直接用SVG viewBox单位当像素。
- 接收物是窗口内16–20px的符号化图片小片，不必读取用户原图生成缩略图，更不能在dragover提早读取文件。多张显示两张轻叠或小数量即可；不会出现窗口外“飞来图片”的虚假轨迹。
- 从drop事件转为完整接收状态而不是一个布尔dragOpen：至少idle/over/receiving/success/error。小球自身拖窗状态独立，正在移动窗口时不张口。
- 使用task id防止旧异步导入结果覆盖新反馈；重复dragenter通过深度计数去抖，内部SVG子节点切换不能导致嘴反复闪开。
- motion=0/系统减少动态：仍以静态口型/状态表达“可接收、处理中、成功”，禁用飞入与弹跳；保持功能信息而不是彻底无反馈。

**成功勾偏移的直接修正**
- `.collapsed-shell span`的宽泛文字规则必须缩窄：它当前给`.drop-feedback`额外margin-top/line-height/font-size/color，覆盖徽章的局部样式；不能仅再写一个更大的!important补丁。
- 勾改为固定viewBox的内联SVG（如24×24，stroke 2、圆端点），容器固定方形，display:grid/place-items:center、margin:0、line-height:0。
- 徽章放在固定布局层，位置锚定球体/容器，不能继承吞咽缩放；图标绘制中心与容器中心一致，视觉中心可用≤1px微调而非top负数试凑。
- 成功期暂时弱化计数或让计数与勾互斥，结束恢复计数；不得因新反馈丢掉数量信息，也不让徽章被88px边界裁切。
- 验收必须看张口、图片小片入嘴、闭口、勾稳定四个关键帧及实际播放；只有代码有keyframes或主体scale不是通过。

## 6. 反馈与操作打磨

1. **单一通知出口**：忙/成功/错误不重叠。普通粘贴/复制/分类成功默认2秒后退出（退场约140ms），无需点击；信息提示3秒。使用事件id而不是message字符串驱动时钟，同文案连续触发也能重置；替换时清理旧timer，隐藏/折叠后过期消息不可复活。鼠标hover/键盘focus可暂停并在离开后继续，长错误显式关闭；恢复数据警告不按普通成功自动丢失。popover出现与通知互不遮挡，aria-live礼貌播报。
2. **折叠态错误可见**：88×88内仅放简短标识与可访问描述，点击展开后看具体错误；不把整段错误塞入小球窗口。
3. **加载失败有退路**：当前loading-card在88×88内有被裁切风险。显示适合小窗口的可点击错误状态，或复用setExpanded打开已有恢复面板；不要增加原生错误窗口。
4. **焦点与键盘**：弹层进入聚焦，Tab限制在模态内，Esc只关最上层，关闭恢复原焦点；确认删除默认焦点在取消。输入框的复制/粘贴/删除不被全局行为抢走。
5. **小球可访问**：补button语义、tabIndex和Enter/Space打开；与原pointer/mouse长按互斥去重，不生成额外click导致双开。
6. **操作期间防重入**：统一现有复制/分类/移除中的忙状态，相关按钮禁用，其余查看/关闭行为按安全性保留；不全界面无差别锁死。
7. **小地图持久化**：拖动只更新本地显示，结束提交最终位置；卸载/取消/失败有确定处理。不能每帧返回完整状态触发无谓重绘。
8. **顶栏拖动**：若WebView2不支持现有CSS拖动区域，复用既有窗口命令；按钮/输入与小球drop区域排除。无需新增API能力。

## 7. 性能与低动态偏好

- prefers-reduced-motion必须同时约束CSS和BotEngine/RAF，不是仅将CSS压到0.01ms。
- 静态品牌标识不启用RAF/全局光标监听；设置页最多一个主动预览实例。
- document隐藏时暂停引擎与订阅；恢复时保持时间连续，不能补播离开期间的动画。原生最小化/隐藏信号与WebView可见性不同则按实测补齐。
- 页面可见但不活跃的预览只在必要时更新；“离开小球即暂停”不能破坏已选择的指针跟随功能。
- 避免持续blur/filter/大阴影动画；优先transform/opacity。不要长期对所有元素加will-change。
- 默认静置明显比当前更安静；活跃拖动/回弹争取60Hz顺滑。帧耗时16.7ms是60Hz目标参考，不宣称当前已实测达成；高刷新率、慢机器以真实采样记录为准。
- 不为追求低占用牺牲拖放/剪贴板成功率，不把大量图片数据与动画逐帧状态绑在一起。
